# Rationale template

Use only the sections that explain a decision the code cannot show. Keep
the note short. Put caller examples and signatures in the sketch.

## Problem

State the required behavior and the constraints found in Phase A.

## Usage and shape

Point to the caller examples and type sketch. Explain state ownership,
validation boundaries, and the complexity hidden by the public interface.

## Decision and alternatives

Name the selected structure and why it won. Name the other structure and why
it lost. Record any useful part taken from another candidate.

## Tradeoffs and open questions

State the cost accepted for the selected benefit. List unresolved questions
that affect implementation.

## Next implementation step

Name the first unit that can be built and verified.
