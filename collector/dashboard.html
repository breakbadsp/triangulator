What is measured · setup

Received and sent bytes are the successful byte counts reported by observed kernel socket operations. Sent means accepted by the socket, not delivered to the peer. Peeks, failed operations and UDP are excluded. A receive operation can contain part of one message or many messages.

Messages processed counts calls to an explicit application completion marker, one call per successfully processed message. It is never inferred from read calls or bytes.

Start the optional source on the target host: build/triangulator-socket-sampler PID COLLECTOR-IP:PORT build/socket.bpf.o. Add MARKER-BINARY MARKER-SYMBOL for completion counts. The source needs kernel BTF, socket length tracepoints and BPF tracing privileges. The normal sampler continues without extra privileges. See docs/socket-ingress-design.md for coverage and setup.

States come from the thread's scheduler state and kernel wait channel (/proc/<tid>/wchan), readable without extra privileges; futex waits cannot be split into lock, condition or timed idle. CPU alerts open after a thread stays above the threshold for the configured duration (default 5 seconds). Thread-table read/write rates mix read- and write-family syscall traffic and do not cover every receive API. Use the socket panel for explicitly observed socket operations. Timelines show sampled state mixes, not exact execution. CPU is per thread, relative to one core.
