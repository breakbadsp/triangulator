      Why does control use Python?
      The dashboard reuses the helper used by scripts/set-target.sh and scripts/set-rate.sh. It finds the local sampler, reads its configuration, checks edits, and requests a reload.
      Each control request starts a short Python process. Opening the panel also uses it to read the target list. It exits after the request. It does not collect samples.
      The documented requirement is Python 3.11+. Python 3.6.8 lacks functions this helper uses, such as str.removesuffix() and Path.is_relative_to(). Python is a dependency of the current control helper. Multi-target sampling itself runs in C++.
      
    
      What stays shared?
      • One sampler monitors all configured targets on each host.
      • Each target has its own session. A reload keeps sessions for unchanged selectors when global settings stay the same.
      • The collector routes samples by session. TTGT announcements map sessions to a host and target ID.
      • Add and remove change monitoring for every viewer. A target selector changes only its browser tab.
      • The default CPU budget is 1% of one core. The sampler reduces the shared rate when needed. This is a budget, not a hard limit.
      
  
      
  
      Why can “Manage targets” be missing?
      The collector enables local control only when its HTTP listener and all configured sampler source addresses are loopback addresses. For example, http_host = "0.0.0.0" disables this control.
      The helper must be at ../scripts/sampler_control.py relative to the directory of the collector executable. A compatible python3 must be on the collector process PATH. The sampler must run locally as the same user, with a writable configuration, and send to this collector. An error can also leave the panel unavailable.
      A Git pull alone does not replace a running collector. From the updated checkout, run scripts/restart.sh all, then reload the dashboard. Preserve the active configuration. For remote samplers, edit their configuration or run the control scripts on the sampler host.
      Check the response on the collector host: curl -sS http://127.0.0.1:9401/api/targets/control. Use the configured HTTP port.
      
  
      Limits, removal, and process restarts
      The sampler accepts at most 16 targets. The collector has max_targets = 8 slots by default. Control checks capacity and keeps at least one configured target.
      A process name follows restarts. A fixed PID identifies one process. A missing process is shown as absent. An ambiguous process name is also absent.
      Manage targets removes a target from the list at once. Removal through a script or a remote configuration can leave a silent target until target_idle_expiry_s passes (600 seconds by default). Recorded history remains available.
